METHODOLOGY HUB

Every score should be explainable.

AtlasIQ exposes the assumptions behind its outputs, separates observed data from modeled signals, and identifies where uncertainty enters the system.

01

Semester Balance

Combines estimated course effort, work, activities, sleep, commute, credit load, and difficulty. The output is a planning heuristic—not an academic prediction.

02

Ripple Engine

Applies transparent directional assumptions to a baseline state and reports bounded ranges. It is designed for comparing tradeoffs, not forecasting certainty.

03

Career + Opportunity

Uses normalized skill dictionaries and ProofGraph evidence coverage. Match scores describe overlap with AtlasIQ's role profile or pasted posting, not hiring probability.

04

Studio Analytics

Infers basic schema, missingness, IQR outliers, Pearson relationships, and lightweight holdout models entirely in browser JavaScript.

05

Atlas Nexus

Aggregates available workspace signals with transparent weights and a completeness adjustment. Missing modules reduce confidence instead of silently becoming perfect scores.

06

Public Data Provenance

World Bank Indicators, USGS GeoJSON feeds, and the BLS Public Data API are displayed with source labels. Live fetches are marked; fallbacks are explicitly identified as cached examples.

Privacy boundary

Profiles, planning state, evidence, decision memory, and uploaded CSV rows are processed locally. The only network requests made by this static release are explicit public-data reads and links the visitor chooses to open.

TECHNICAL METHODOLOGY

How this static release works

Semester: weighted load heuristic using course hours/difficulty, outside commitments, sleep, credits, and commute. The model is transparent and comparative.

Career: normalized skills are compared with role-specific dictionaries; ProofGraph evidence contributes to confidence.

Studio: schema inference, missingness, IQR outlier flags, Pearson correlation, simple local baselines, linear regression, and nearest-neighbor models. A deterministic holdout is used for quick browser evaluation.

Nexus: available module scores are normalized to 0–100 and combined with explicit weights; completeness reduces confidence when modules have not been used.

Public data: browser fetches target official public endpoints. When a live request fails, the interface states that it is showing a cached example instead.
